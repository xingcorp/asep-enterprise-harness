# Phase 2 — Data Model (LOCKED)

> Companion to `phase-02-plan.md`. PostgreSQL 17 (compose already provisions it). Base `e046885`.
> Adjudication of Codex plan review folded in (see `phase-02-review-log.md`): HIGH-003 (composite FK + TenantScope), HIGH-004 (scope-aware artifacts), HIGH-005 (crash-safe side-effect protocol), HIGH-010 (ExecutionEnvelope schema + RunEvent fields), MED-006 (migration locking/transaction/re-apply).

## 1. Conventions

- **Identifiers**: ULID (`char(26)`), lexicographically sortable, generated by the harness. Branded string types in TS (`ProjectId`, `RunId`, …) already exist in `@asep/contracts`; add `OrganizationId`, `RepositoryBindingId`, `WorkspaceId`, `CommandExecutionId`, `PullRequestId`.
- **Timestamps**: `timestamptz`, always UTC.
- **Concurrency**: every mutable aggregate carries `version integer not null default 0`; updates use `WHERE id = $1 AND version = $2` and bump version (optimistic lock).
- **TenantScope / AuthContext (disp. P2-PLAN-HIGH-003)**: a `TenantScope { organizationId, projectId }` value is **derived from authenticated server state** (auth-local adapter / request principal), never from client-supplied body fields. Every application use case and every repository method takes `TenantScope` as its first parameter and filters on it. A row's `(organization_id, project_id)` is validated against the scope before any read/write returns.
- **Hierarchy consistency (disp. P2-PLAN-HIGH-003)**: duplicated `organization_id`/`project_id` columns are not protected by single-column FKs alone. Each child declares a **composite foreign key** onto its parent's `(id, organization_id, project_id)` (parent carries a composite unique key), so a task cannot reference a run/binding from another project and still pass a scoped filter. Cross-parent mismatches fail at the database boundary.
- **Transactions**: one checked-out `pg` client from `BEGIN` to `COMMIT/ROLLBACK` (node-postgres pooling contract).
- **Migrations (disp. P2-PLAN-MED-006)**: append-only, numbered, checksummed; applied migrations are immutable; forward-tested on a clean database in CI. An **advisory lock** (`pg_advisory_lock`) serializes concurrent migrators; each migration runs in a transaction where PostgreSQL permits (DDL is transactional); a second no-op apply is asserted; a partially-applied non-transactional migration has a documented recovery policy; an edited applied migration fails on checksum before any later migration runs.
- **Secrets**: no plaintext provider token or private key. GitHub App private key lives out of DB (controller/secret store). Only non-secret installation metadata is stored.

## 2. Hierarchy

```text
organizations 1─* projects 1─* repository_bindings 1─* runs 1─* tasks 1─* attempts
                                                                          attempts 1─0..1 pull_requests
attempts *─1 workspace_leases (active)   attempts 1─* command_executions   attempts 1─* artifacts (metadata)
audit_events, idempotency_records span all.
```

## 3. Tables (columns abbreviated to the load-bearing set)

### organizations
`id ulid pk`, `name text`, `created_at`, `version`.

### projects
`id pk`, `organization_id fk`, `name`, `default_branch text`, `created_at`, `version`. Unique `(organization_id, name)`.

### repository_bindings
`id pk`, `organization_id fk`, `project_id fk`, `forge text check in ('github')`, `github_host text check in ('github.com', configured GHES host)`, `github_owner text`, `github_repo text`, `github_installation_id bigint`, `github_repository_id bigint`, `default_base_branch text`, `created_at`, `version`. Unique `(project_id, github_host, github_owner, github_repo)`. No token column. Declares composite unique `(id, organization_id, project_id)` so children can compose-FK onto it.
**No arbitrary `remote_url` (disp. P2-PLAN-HIGH-007).** Clone/fetch URLs are **constructed** from the validated `(github_host, github_owner, github_repo)` identity, never stored as or accepted as a free transport string. This forecloses `file://`/`ext::`/`ssh`/local-path/userinfo/option-injection transports at the data layer.

> **Hierarchy consistency via composite FKs (disp. P2-PLAN-HIGH-003).** Duplicated `organization_id`/`project_id` columns are NOT protected by independent single-column FKs (that lets a task claim project A while pointing at a run from project B and still pass a scoped row filter). Instead each parent declares a composite unique `(id, organization_id, project_id)` and each child FKs onto **that composite**, so the DB rejects any org/project mismatch between a row and its parent. Every table below carries the scope columns AND the composite FK.

### runs
`id pk`, `organization_id`, `project_id`, `repository_binding_id`, `status text` (Phase-1 `RunStatus`), `product_spec_ref jsonb` (ArtifactRef), `risk text check in (R0..R4)`, `created_at`, `version`. Composite FK `(repository_binding_id, organization_id, project_id)` → `repository_bindings`. Composite unique `(id, organization_id, project_id)`.

### tasks
`id pk`, `organization_id`, `project_id`, `run_id`, `repository_binding_id`, `status text` (see §4), `risk text`, `work_order_ref jsonb` (ArtifactRef → immutable WorkOrder), `work_order_schema_version text`, `base_sha text`, `created_at`, `version`. Composite FK `(run_id, organization_id, project_id)` → `runs`. Composite unique `(id, organization_id, project_id)`. `repository_binding_id` carried for direct repository resolution (disp. P2-PLAN-HIGH-003).

### attempts
`id pk`, `organization_id`, `project_id`, `task_id`, `repository_binding_id`, `status text` (see §4), `base_sha text`, `result_sha text null`, `agent_provider_id text`, `agent_model text`, `context_pack_ref jsonb null`, `evidence_bundle_ref jsonb null`, `failure_class text null`, `usage jsonb null`, `started_at`, `ended_at null`, `version`. Composite FK `(task_id, organization_id, project_id)` → `tasks`. Composite unique `(id, organization_id, project_id)`. Index `(task_id, started_at)`.
`result_sha` semantics (disp. P2-PLAN-HIGH-008): the **final harness-owned commit SHA**, written only after the harness commit exists; never a provider-supplied or pre-commit SHA.

### workspace_leases
`id pk`, `organization_id`, `project_id`, `repository_binding_id fk`, `branch text`, `attempt_id fk`, `workspace_id text`, `state text check in ('ACTIVE','RELEASED','EXPIRED','QUARANTINED')`, `acquired_at`, `heartbeat_at`, `expires_at`, `version`.
**Unique active-writer constraint**: `create unique index one_active_writer on workspace_leases (repository_binding_id, branch) where state = 'ACTIVE'`. A second concurrent acquire violates it → `LeaseDenied`.

### artifacts
`id pk`, `organization_id`, `project_id`, `attempt_id null`, `kind text`, `sha256 text`, `size_bytes bigint`, `storage_key text`, `content_type text`, `created_at`. Unique `(organization_id, project_id, sha256, kind)` (tenant-scoped dedup). Composite FK on `attempt_id` when present. Composite unique `(id, organization_id, project_id)` so authoritative references FK onto scoped artifact identity, not an arbitrary JSONB ref (disp. P2-PLAN-HIGH-004).
**Scope-prefixed key + create-only (disp. P2-PLAN-HIGH-004).** `storage_key = <organization_id>/<project_id>/sha256/<sha256>` — tenant/project-namespaced, never a user path. Object writes are **conditional create-only** (S3 `If-None-Match: *` / filesystem `O_EXCL`): concurrent different-byte writes to one key fail rather than overwrite. Size + checksum are verified before the metadata row is committed and re-verified on every read; mismatch fails closed. Orphan reconciliation: if metadata commit fails after an object write, the create-only object is a byte-identical no-op for the next identical put, and a reconciliation sweep records orphans. Authoritative links (`*_ref` columns) are scoped FKs carrying artifact id + expected checksum, not free JSONB.
> **`ArtifactStore` is scope-aware (disp. P2-PLAN-HIGH-004).** Every `put/get/verify` takes a `TenantScope`; project A cannot read, verify, infer existence of, or attach project B's object. A cross-scope reference fails closed.

### command_executions
`id pk`, `organization_id`, `project_id`, `attempt_id fk`, `command_id text`, `executable text`, `args jsonb`, `exit_code integer null`, `signal text null`, `timed_out bool`, `duration_ms numeric`, `stdout_artifact_id fk null`, `stderr_artifact_id fk null`, `environment_profile text`, `executable_version text null`, `created_at`. Raw stdout/stderr are artifacts (never truncated inline).

### pull_requests
`id pk`, `organization_id`, `project_id`, `repository_binding_id fk`, `attempt_id fk`, `forge text`, `number integer`, `head_branch text`, `base_branch text`, `url text`, `state text`, `evidence_bundle_ref` (scoped FK), `created_at`, `updated_at`, `version`. `repository_binding_id` is **declared here** (disp. P2-PLAN-HIGH-003 — the v1 unique index referenced an undeclared column). Composite FK `(repository_binding_id, organization_id, project_id)`. Unique `(repository_binding_id, head_branch)` supports idempotent upsert. No merge column.

### audit_events
`id pk`, `organization_id`, `project_id`, `run_id null`, `task_id null`, `attempt_id null`, `actor text`, `action text`, `occurred_at`, `detail jsonb`. Append-only.

### side_effect_records  (was `idempotency_records` — redesigned per disp. P2-PLAN-HIGH-005)
`id pk`, `organization_id`, `project_id`, `repository_binding_id char(26) not null`, `attempt_id char(26) not null`, `operation text check in ('commit','push','pr-upsert')`, `request_fingerprint text`, `state text check in ('PENDING','COMPLETED','FAILED')`, `owner_token text` (fencing), `result_ref jsonb` (closed shape, see below), `natural_key text` (remote reconciliation key, e.g. head_branch), `created_at`, `updated_at`, `version`. Unique `(organization_id, project_id, repository_binding_id, attempt_id, operation)` — **tenant-scoped and typed**, not global and not text.

**DB coherence (migration 0013, cycle-6 HIGH-005).** Composite FK `(repository_binding_id, organization_id, project_id)` → `repository_bindings` (0012) and composite FK `(attempt_id, organization_id, project_id, repository_binding_id)` → `attempts`, so a record can only name a binding in its own tenant **and** only its attempt's binding. The text columns `scope` and `semantic_key` that 0007 keyed on are dropped; nothing keys on text.

**Closed outcome.** `result_ref` is `NULL` unless `state = 'COMPLETED'`; when COMPLETED it is exactly one of `{kind:'commit',commitSha,evidenceId}`, `{kind:'push',branch,commitSha}`, `{kind:'pr-upsert',number,url,headBranch,baseBranch}` for its operation, with no extra keys, a 40-hex SHA, a ULID evidence id and an http(s) PR URL. The CHECK `side_effect_result_closed` (function `asep_side_effect_result_valid`) enforces this in the database; `SqlSideEffectLog.complete()` validates with `parseSideEffectResultRef` before writing and parses again on read; `SideEffectCompleteInput` in `packages/ports` pins the shape to the operation at the type level.

**Crash-safe side-effect protocol.** A result-only row cannot atomically cover an external Git/GitHub side effect: a crash after push but before recording replays the push. Each side effect (commit, exact-ref push, PR upsert) runs: (1) insert/claim a `PENDING` row with a fencing `owner_token` and the `request_fingerprint`; (2) perform the external op; (3) mark `COMPLETED` with `result_ref` + `natural_key`. On restart, a `PENDING`/`FAILED` row triggers **reconciliation by natural key** (does the remote ref / PR / commit already exist?) rather than blind replay. Reuse of a `semantic_key` with a **different** `request_fingerprint` fails closed (a new business intent must not reuse a completed key). Fault-injection tests kill the executor immediately before and after each Git/object/GitHub call and before/after the DB write; restart must converge to exactly one commit, one expected remote ref and one PR.

## 4. State machines

### Task
```text
PENDING → READY → EXECUTING → VERIFYING → WAITING_FOR_HUMAN_REVIEW
                     ↓            ↓
                   FAILED       FAILED
  any non-terminal → CANCELLED
```
No transition from machine states into an `ACCEPTED`/`DONE` state exists in Phase 2. `WAITING_FOR_HUMAN_REVIEW` is terminal for the harness; only a human (out of scope for automation here) advances it.

### Attempt
```text
STARTED → AGENT_RUNNING → AGENT_DONE → INSPECTING → VERIFYING → EVIDENCE_BUILT
        → COMMITTED → PUSHED → PR_OPEN → SUCCEEDED
any → FAILED (classified) | BLOCKED | BUDGET_EXHAUSTED | CANCELLED
```
Transitions are explicit functions in `packages/domain` with table-driven allow-lists (mirrors the existing `transition()` pattern) and are concurrency-checked via `version`.

### WorkspaceLease
```text
ACTIVE → RELEASED | EXPIRED | QUARANTINED
```
Expiry is driven by `expires_at` + heartbeat; a stale `ACTIVE` lease past `expires_at` is swept to `EXPIRED` before a new acquire can win, and its workspace is `QUARANTINED` (never reused).

## 5. Migration set (S2)

```text
0001_init_tenancy         organizations, projects, repository_bindings
0002_runs_tasks_attempts  runs, tasks, attempts + state check constraints
0003_workspace_leases     leases + one_active_writer partial unique index
0004_artifacts            artifacts + tenant sha256 unique
0005_command_executions   command_executions
0006_pull_requests        pull_requests + head_branch unique
0007_audit_side_effects   audit_events, side_effect_records
0008_binding_scoped_fks   binding-scoped composite FKs
0009_scoped_evidence_refs scoped evidence references
0010_human_authorizations human authorization records
0011_hierarchy_binding_coherence  binding carried coherently down the hierarchy
0012_side_effect_binding_fk       side_effect_records.repository_binding_id + scoped FK
0013_side_effect_records_closed   typed identity (attempt_id, operation), attempt-binding FK,
                                  text keys dropped, closed result_ref CHECK
```

Each migration has a checksum recorded in a `schema_migrations` table; re-running an altered applied migration fails closed. A clean-DB forward test asserts the full set applies and the resulting schema matches expectation.

**Migration execution rules (disp. P2-PLAN-MED-006).** A single migrator holds an advisory lock (`pg_advisory_lock`) so two concurrent migrators cannot race. Each migration runs in a transaction where PostgreSQL allows it (DDL is transactional in PG); a mid-migration failure rolls back and the migration is not marked applied. Re-applying the full set on an already-migrated DB is a no-op (idempotent). Applied migration files are immutable — an edited checksum fails **before** any later migration runs. Real-PostgreSQL tests: apply twice (second run no-op), two migrators concurrently (one waits, neither corrupts), inject mid-migration failure + restart (converges), reject an edited applied migration.

## 6. Mapping to Phase 1 contracts

- `WorkOrder`, `ContextPack`, `EvidenceBundle`, `RunEvent`, `ReviewReport` remain the canonical Phase 1 schemas; Phase 2 stores **references** (`ArtifactRef`) to immutable instances, not exploded columns.
- `RunEvent` rows drive telemetry/metrics; every emitted event carries `runId/taskId/attemptId/projectId` (fields already in the schema). **RunEvent gets a governed minor bump to `run-event/v1.1.0` (disp. P2-PLAN-HIGH-010)** adding two OPTIONAL fields — `organizationId` and `repositoryBindingId` — which is additive-safe under `COMPATIBILITY.md` (new optional = minor, no `$id` major change). This satisfies exit criterion J2 (every event resolves to org + repository) without breaking `run-event/v1` consumers. The compat gate + snapshot must cover the bump; `run-event-catalog.ts` and the metrics-dictionary referential-integrity validator are updated in lockstep.
- `EvidenceBundle` (schema already present, with `checks[].stdoutArtifactId/stderrArtifactId`) is produced from `command_executions` + `artifacts` — the Phase 1 schema anticipated exactly this shape.
- No provider SDK type is persisted; `usage` is a plain JSON projection of the Phase 1 `Usage` contract.
