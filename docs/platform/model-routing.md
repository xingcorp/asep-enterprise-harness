# Model Routing

Routing uses task type, risk, language/framework, context/tool needs, historical pass rate, cost, latency, provider health and required review independence. Model and harness versions are pinned per attempt.

Promotion requires internal eval and shadow/canary evidence. A public benchmark win is insufficient. Review policies may require a different provider/family for R2–R4, but deterministic assurance remains the primary gate.

Fallbacks must preserve capability requirements: tool use, structured output, context size, cancellation and data residency. A cheaper model is not a valid fallback if it cannot satisfy the WorkOrder contract.
